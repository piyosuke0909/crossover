# Crossover 受け入れテスト・公開運用チェックリスト

対象ブランチ: `feature/paypay-blue-ui-admin`
確認目的: 名刺解析、公開設定、プレビュー兼確認、検索対象制限、既存登録・管理の回帰を確認する。

## 自動テスト

`npm test`（Node.js + tsx --test）。GitHub Actionsでは `Lint → Unit tests → Build` の順に実行する。

- 名刺解析の成功Cookie署名・有効期限・改ざん検知
- 公開電話番号・住所の初期値が非公開であること
- 公開可否がユーザー指定でONにできること
- 参加者名検索が対象イベントの EventPerson のみを検索すること

## 運用前に必須

1. `npm run db:deploy` を本番DBへ適用（公開表示設定の新カラムが必要）
2. 開発環境・Vercel環境の `GEMINI_API_KEY` と `PARTICIPANT_AUTH_SECRET` の設定を確認
3. PreviewでTC01〜TC22を確認してから本番へ反映
4. 企業担当者へ電話番号・住所の公開可否を確認し、本人同意を得てONにする

## 制限事項（重要）

- **解析成功1回の制限は同一ブラウザの署名付きCookieで判定**している。
- 本人確認前の名刺解析のため、別端末・プライベートブラウズ・Cookie削除をまたいだ同一人物の判定はできない。厳密な「1人1回」には、先に本人確認（例: メールOTP）してから解析する設計への変更が必要。
- サーバーエラー・不正画像・読み取り結果が空の場合は解析成功としてカウントしない。
- 会社の公開設定は会社単位で共有され、所属担当者による変更も会社全体に反映される。
- メールアドレスは公開企業画面に表示しない。管理者CSVは公開設定の対象外。
- CIはDBを伴うE2Eまでは行わないため、手動受け入れ試験の完了前に実運用可能と判断しない。
