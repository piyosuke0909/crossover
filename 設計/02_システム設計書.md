# システム設計書

## 1. システム構成方針

Webブラウザから利用するレスポンシブWebアプリケーションとする。

主な利用端末はスマートフォンを想定するが、管理画面はPC利用も想定する。

## 2. 基本構成

- フロントエンド
- バックエンドAPI
- データベース
- 画像ストレージ
- 管理画面

具体的な技術スタックは未確定。

## 3. URL構成イメージ

- `/events/{eventId}` 交流会トップ
- `/events/{eventId}/register` 登録
- `/events/{eventId}/companies` 参加企業一覧
- `/companies/{companyId}` 企業詳細
- `/persons/{personId}` 担当者詳細
- `/admin` 管理画面
- `/admin/events` 交流会管理
- `/admin/companies` 企業管理

## 4. データ管理方針

企業情報と交流会参加情報を分離する。

企業そのものは使い回せるようにし、各交流会との参加関係だけを紐づける。

担当者も同様に企業に所属し、交流会ごとに参加状態を管理する。

## 5. 認証方針

### 参加者
ログイン必須にはしない。

プロフィール編集・次回参加時の再利用には、再登録キーまたは編集キーを利用する方針。

### 管理者
管理者認証を必須とする。

## 6. 検索

MVPでは以下を対象とする。

- 企業名
- 担当者名
- 事業内容
- 企業プロフィール
- 業界

高度な全文検索エンジンは使用せず、通常のDB検索で実装可能な範囲を想定する。
