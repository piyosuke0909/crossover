# Crossover | 常設の企業交流スペース

お酒を嗜みながら企業の方と交流する場で使う、シンプルな企業・担当者ディレクトリです。

## 利用者向け
- トップページ `/` は常設の交流ページに移動します。イベント一覧はありません。
- 企業一覧・企業検索・企業詳細・個人QRの担当者プロフィールは、ログインした参加者だけが閲覧できます。
- 登録後に個人QR・「話した人」の記録・プロフィール編集を利用できます。
- 名刺AIスキャンは廃止しました。本人の顔写真アップロードは引き続き必須です。
- 電話番号と住所は明示的に公開を許可した場合のみ表示します。
- フォームは200文字以内の入力制限を維持し、長文を折り返します。

## 管理者向け
`/admin` から企業・担当者と常設ページの情報を管理します。
イベントの新規作成・削除・参加者移行機能は廃止しています。
既存のイベントと登録データは消さず、1件を使い回します。
管理画面の「会場QR」はいつでも同じトップURL `/` に接続します。

**すでにイベントが複数ある場合**は `CROSSOVER_EVENT_ID`（任意）に常設で使うイベントのIDを設定して固定してください。
未設定の場合は、登録企業＋担当者が最も多い既存イベントを自動選択します。
同点では新しいイベントを優先します。古いイベントの履歴は統合・削除されません。

## 開発
```bash
npm ci
npm run db:deploy
npm run db:seed
npm run dev
```

必要な環境変数の例は `.env.example` を参照してください。
基本機能には `DATABASE_URL`、`BLOB_READ_WRITE_TOKEN`、`ADMIN_PASSWORD`、`PARTICIPANT_AUTH_SECRET` が必要です。
メールOTPにはGmail APIの認証情報が必要です。Gemini APIキーは不要です。

## 確認
```bash
npm run lint
npm test
npm run build
```

実ブラウザで、ログアウト状態の企業検索とスマホ画面幅（特に320px）を最終チェックしてください。

## 参加者ログインと企業情報の保護
- 企業一覧と詳細はサーバー側で有効な参加者セッションを検証します。未ログインならログイン画面へ移動します。
- 登録前の「所属企業を選択」検索は新規参加者に必要なため使えますが、返す情報は企業ID・企業名・業界だけです。企業の紹介・住所・電話・担当者情報は返しません。
- 非公開イベント、非表示担当者・企業、期限切れまたは無効なセッションでは閲覧できません。
- 新しくプロフィールを登録した場合、その端末にはログイン済みセッションを発行します。
